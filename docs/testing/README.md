# Testing guide

Conventions for automated tests in this project. Follow these when adding or changing tests.

- [Test structure: Given / When / Then](given-when-then.md)
- [The `prepareScenario` factory](prepare-scenario.md)
- [Fakes & coroutine testing](fakes-and-coroutines.md)

## At a glance

- Only the shared Kotlin is unit tested: use cases, repositories, mappers, the `SyncCoordinator`, the
  `BackStackNavigator` and every ViewModel. The ViewModel tests are where a screen's behavior is specified, for the
  three UIs at once. The Compose, SwiftUI and React layers have no automated tests; they are checked by running the
  app on each platform.
- Tests live in each module's `src/commonTest` and run on the `jvm` target: `./gradlew jvmTest` for all of them,
  `./gradlew :feature:restore:jvmTest` for one module. The Android library targets don't enable host tests, so
  `commonTest` does not run on the Android host.
- Stack: `kotlin.test` + `kotlinx-coroutines-test`. No mocking library: collaborators are faked by hand, and the
  fakes of `:core:account` and `:core:profile` are shared through their `:testing` modules.
- Every test body is split into **Given / When / Then**, and its name says the same in
  `` `GIVEN … WHEN … THEN …` `` form.
- Each test class ends with a single `prepareScenario(...)` that assembles the system under test and its fakes.
- Test names may only hold letters, digits, spaces, `-` and `_` ("the code of the old device", not "the old
  device's code").
- ktlint enforces the structure on every test source set: the names, the three sections and the `prepareScenario`
  rules are custom `quare` rules (`./scripts/ktlint.sh`). See the Enforcement sections of
  [given-when-then.md](given-when-then.md#enforcement) and [prepare-scenario.md](prepare-scenario.md#enforcement).

## What is covered where

| Code | Test class | Collaborators |
| --- | --- | --- |
| ViewModel | `feature/<name>/src/commonTest/.../XViewModelTest.kt` | Real use case implementations over `FakeAccountRepository` / `FakeProfileRepository`, lambdas for single-call use cases, a real `BackStackNavigator`, `NetworkConnectivityObserver { isOnline }` |
| Repository | `core/<name>/src/commonTest/.../data/XRepositoryImplTest.kt` | Private fakes of its local and remote data sources, at the end of the file |
| Use case with logic | `core/<name>/src/commonTest/.../XUseCaseTest.kt` | The shared fakes |
| `SyncCoordinator` | `core/sync/src/commonTest/.../SyncCoordinatorTest.kt` | The shared fakes, a `MutableStateFlow` for connectivity, `backgroundScope` as its scope |
| Pure logic | next to it (`RecoveryCodeFormatTest`, `BackStackNavigatorTest`) | none |

A ViewModel test asserts what the person would see or where they end up: `viewModel.uiState.value`, the collected
`UiAction`s, `navigator.backStack.value`, and the calls recorded by the fakes (`account.restoredCodes`,
`profiles.savedProfiles`).

## Coverage

[Kover](https://github.com/Kotlin/kotlinx-kover) measures the line coverage of the tests that run on the `jvm`
target and fails under **80%** of the merged report:

```bash
./gradlew :koverVerifyCi       # the 80% rule
./gradlew :koverHtmlReportCi   # build/reports/kover/htmlCi/index.html
```

The colon matters: without it Gradle runs the task of the same name in every module. `ci` is a Kover variant
(`configureCoverage` in `build-logic`) that holds only the `jvm` target, so each module's tests run once.

### What Kover measures

The root `build.gradle.kts` merges `:core:*` and `:feature:*`, and leaves out:

| Excluded | How | Why |
| --- | --- | --- |
| `*.di` | package filter | Koin modules: wiring, no behavior of their own |
| `*.bridge` | package filter | `FlowWatcher`, `ViewModelHolder`, the Apple and JS bridges: exercised by the apps |
| `*_Impl`, `*_Impl$*`, `*$$serializer`, `*$DefaultImpls`, `*.generated` | class and package filters | generated by Room, kotlinx.serialization and BuildKonfig |
| `:core:*:testing` | Kover is not applied (`configureCoverage`) | the shared fakes are test code, even though they live in `commonMain` |
| `:core:provider:*` | not merged | the database and client setup of each platform |
| `:shared`, `:android:*`, `:androidApp`, `iosApp/`, `webApp/` | not merged, or not Gradle | the composition root and the three UIs |

Excluding more code is a change to that table and to the filters, reviewed like any other: the default for new
code is to be measured and tested.
